# 코스튬 원본 전수 검수 및 세트 분리 설계

## 목표

도감의 모든 코스튬 원본 PNG를 한 장씩 확대 검토해 잘림, 반투명 노이즈, 과도하게 작은 그림, 구성품 합침을 제거한다. 이름에 `세트`가 붙은 19개 항목은 실제 구성품별 독립 도감 카드와 독립 PNG로 분리한다.

첨부 화면은 코스튬을 감자봇에 착용한 합성 결과이므로 감자봇의 몸, 눈, 입, 팔, 다리는 원본 결함 판정 대상이 아니다. 검수 대상은 `pack/<rarity>/*.png`의 아이템 레이어 자체다.

## 범위

- 기존 비기본 코스튬 156종의 원본 PNG 전수 수동 검토
- 이름에 `세트`가 포함된 19개 항목의 구성품 분리
- 잘림·노이즈·과소 크기·불명확한 디테일이 있는 원본 재제작
- 분리 뒤 도감 메타데이터, 뽑기 풀, 보유·착용 저장 데이터 호환
- 원본 단독 시트와 착용 합성 시트의 이중 시각 QA
- 자동으로 판정 가능한 여백·노이즈·크기·누락 검사 보강

다중 코스튬 동시 착용은 이번 범위에 넣지 않는다. 분리된 구성품은 각각 독립적으로 한 개씩 착용한다.

## 원본 자산 합격 기준

각 PNG는 256×256 RGBA 투명 이미지이며 하나의 도감 아이템만 표현한다.

- 주요 불투명 픽셀이 캔버스 가장자리에 닿지 않고 안전 여백을 가진다.
- 아이템 실루엣이 카드에서 식별 가능할 만큼 충분히 크다.
- 의도하지 않은 고립 픽셀, 반투명 먼지, 색 번짐, 체크무늬 잔상이 없다.
- 선과 표면 디테일이 이름과 등급에 맞게 읽힌다.
- 머리·얼굴·목·몸 슬롯의 실제 착용 기준점과 크기가 자연스럽다.
- 하나의 세트에 포함된 서로 다른 착용 부위는 각자 별도 PNG와 별도 카드가 된다.
- 장식상 떨어져 있어야 하는 끈, 안경 다리, 날개, 보석 등은 노이즈로 오판하지 않고 수동 판정 근거를 기록한다.

## 세트 분리 방식

현재 명시적 세트는 19개다. 각 세트를 확대 검토해 모자, 안경, 목걸이, 카메라, 상의, 날개처럼 의미와 착용 부위가 다른 구성품으로 나눈다.

- 기존 세트 ID는 삭제하지 않고 대표 첫 구성품에 유지한다.
- 추가 구성품은 같은 등급의 마지막 번호 뒤에 연속된 새 ID를 받는다.
- 기존 세트의 `source`, `sourceSlot`, `collection`은 모든 파생 구성품에 유지하고 `parentSetId`로 관계를 기록한다.
- 도감 이름에서는 `세트`를 제거하고 구성품의 실제 이름을 사용한다.
- 뽑기 풀은 manifest의 실제 항목을 기준으로 구성해 하드코딩된 156개 제한을 제거한다.
- 분리 후에도 한 번에 하나의 구성품만 착용한다.

## 기존 저장 데이터 호환

`gamcha.json` 스키마를 한 단계 올리고 세트 분리 매핑을 적용한다.

- 기존 세트 ID를 보유한 사용자는 해당 세트에서 파생된 모든 구성품 ID를 자동 보유한다.
- 기존 세트 ID가 착용 중이면 대표 첫 구성품을 계속 착용한다.
- 기존 세트 ID의 사용자 위치 보정값은 대표 첫 구성품에 보존한다.
- 새 구성품은 각자의 기본 정렬값을 사용한다.
- 마이그레이션은 한 번만 실행하고 기존 티켓·누적 추첨·다른 보유 아이템을 변경하지 않는다.
- 손상 저장 파일 보존 규칙은 기존 동작을 유지한다.

## 전수 검토 절차

1. manifest 순서대로 모든 원본을 큰 단독 보기와 착용 합성 보기로 나란히 생성한다.
2. 각 ID에 대해 `keep`, `realign`, `split`, `redraw` 중 하나를 지정한다.
3. 이유는 공통 문구가 아니라 실제 관찰한 결함과 구성품 이름을 기록한다.
4. 세트는 구성품 수와 이름·슬롯을 먼저 확정한 뒤 한 구성품당 한 PNG를 만든다.
5. 잘림·노이즈·과소 크기 자산은 기존 색상·소재·실루엣을 참고해 built-in image generation으로 개별 재제작한다.
6. 재제작 후 동일한 두 시트를 다시 생성하고 모든 변경 항목을 재검토한다.
7. 마지막으로 전체 도감을 처음부터 끝까지 한 번 더 훑어 누락과 새 결함을 확인한다.

## 이미지 생성 규칙

각 자산은 현재 원본을 참조 이미지로 사용한다. 프롬프트는 다음 불변 조건을 반복한다.

- 해당 구성품 하나만 생성
- 원래 아이템의 색상, 재질, 문양, 정체성 보존
- 2D 게임 코스튬 오버레이 스타일과 선명한 외곽선
- 256×256 투명 배경, 전체 실루엣이 잘리지 않게 중앙 배치
- 충분한 안전 여백
- 글자, 워터마크, 체크무늬, 그림자 배경, 임의의 추가 장식 금지
- 다른 세트 구성품을 한 이미지에 합치지 않음

생성 결과는 먼저 후보 폴더에서 검토하고 정규화·검사를 통과한 파일만 production 경로로 승격한다.

## 자동 QA

- manifest ID와 파일 경로의 유일성
- 모든 production PNG의 존재, 256×256, RGBA, 실제 투명 영역
- 불투명 경계의 최소 안전 여백
- 지나치게 작은 불투명 바운딩 박스
- 작은 고립 알파 컴포넌트와 저알파 먼지 후보
- audit 원장에 모든 항목이 정확히 한 번 존재
- `split` 판정에는 두 개 이상의 파생 구성품이 존재
- 파생 구성품 이름에 `세트`가 남지 않음
- parentSetId와 레거시 마이그레이션 매핑의 정합성
- 등급별 뽑기 풀과 manifest 항목의 완전 일치

자동 검사는 후보를 찾는 안전망이며 최종 합격은 접촉 시트의 항목별 수동 확인으로 결정한다.

## 검증

- 자산 QA 테스트와 156종 이상 전체 manifest 검사
- 세트 소유·착용·위치 보정 마이그레이션 Rust 테스트
- 뽑기 풀의 새 동적 항목 수와 중복 방지 테스트
- 도감 카드·미리보기·착용 합성 프런트 테스트
- TypeScript 검사와 production build
- Rust 전체 테스트, rustfmt, Clippy
- 개발 앱에서 대표 head·face·neck·body 구성품과 분리 세트 수동 착용 확인

## 완료 조건

- 기존 156종 모두 실제 원본을 개별 검토한 구체적인 기록이 있다.
- 19개 세트가 의미 있는 개별 구성품 카드로 분리된다.
- 잘리거나 노이즈가 있거나 지나치게 작은 production PNG가 남지 않는다.
- 기존 사용자의 세트 보유 내역이 분리된 모든 구성품으로 안전하게 이전된다.
- 전체 자동 검사와 두 종류 접촉 시트의 최종 수동 검토가 통과한다.
